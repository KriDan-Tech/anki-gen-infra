# Observability provisioning

Static configuration snapshot on branch `metrics` (2026-11-21). Nothing in this change was deployed, started, or runtime-verified. These files do not establish target reachability, metric availability, alert delivery, or deployed state.

## Exporters and private scrape routing

The app Compose stack pins node-exporter `v1.10.2`, cAdvisor `v0.55.1`, nginx-prometheus-exporter `1.5.1`, and nginx-log-exporter `v1.11.0`. Their configurable host binds default to loopback. They have no public Traefik route. To scrape remotely, operators must set bind addresses to a private/VPN interface and separately provide private routing and firewall allow rules from the metrics host to only the required ports. This work changes no ACL/firewall rules and invents no host address.

Set Ansible inventory variables `app_node_exporter_target`, `app_cadvisor_target`, `app_nginx_exporter_target`, and `app_nginx_log_exporter_target` to private `host:port` values; blank values omit those jobs. Optional `app_actuator_targets` configures the application actuator job only when endpoints actually exist. Entries may be legacy `host:port` strings (retained for backward compatibility) or mappings with `service` and `target`; each target is rendered as its own static target with a `service` label when supplied. `app_source_service_metrics_target` is an independent optional private `host:port` target scraped at `/metrics`; it is blank by default and creates no public route. `app_traefik_metrics_target` is optional too (replaces a former hard-coded address). Ensure source-service itself exposes that route on the private network before setting its target.

The app Compose file publishes six host ports (19090–19095) on `0.0.0.0`, all owned by the dedicated `metrics-proxy`; no application container publishes an Actuator port. The proxy forwards only exact `GET /actuator/prometheus` requests to the matching service (gateway container port 9090; billing 8085; card-builder 8083; deck-service 8084; notification 8086; vocab-extractor 8082). All other paths/methods are rejected. It uses Docker DNS resolver `127.0.0.11` for runtime service-name resolution and does not trust forwarded client-IP headers. `METRICS_ALLOWED_CIDR` configures the source allowlist; its Compose-safe default is `127.0.0.1/32` (fail closed for remote scrapers), so set it to the actual scraper CIDR in the application Compose .env (for Ansible, the source infra/.env copied to the app host) before enabling remote scrapes. Deploy app revisions containing the Actuator metrics changes; the Ansible app role defaults to main, so override app_repos revisions on an unmerged metrics branch. Do not infer that source from the app destination `192.168.0.115`. `ansible/host_vars/ecb-metrics.yml` retains six named target labels/destinations; external routing/firewall must permit only the actual scraper source. No firewall or router change, deployment, or runtime reachability is claimed.

The cAdvisor Docker socket bind is marked read-only, but that does not make the Docker API itself read-only. Its endpoint must remain private and tightly firewalled. Grafana and Prometheus host binds default to loopback.

## Grafana file provisioning lifecycle

The Ansible role writes datasource, dashboard-provider, and alert-rule provisioning files below `/opt/metrics/grafana/provisioning`, and copies dashboard JSON to `/opt/metrics/grafana/dashboards`. Provisioning files and dashboard directory are mounted read-only into Grafana; the dashboard provider path is explicitly mounted at `/var/lib/grafana/dashboards`. These source-controlled files are authoritative; UI edits to provisioned dashboards/rules may be overwritten on subsequent provisioning/redeploy. The dashboard provider polls for provisioned dashboard file changes every 30 seconds; this is dashboard-only polling and does not recreate/reconfigure the Prometheus/Grafana role. Role changes require the normal Ansible role deployment/recreation workflow. Manual dashboard import is available via **Dashboards → New → Import**, using `ansible/roles/prometheus_grafana/files/dashboards/infra-overview.json` and datasource UID `prometheus`. The overview retains UID `infra-overview` and the `prometheus` datasource UID. Its default panels show named Actuator UP/DOWN (with an instant query), Prometheus self-scrape health, plus Prometheus-reported application scrape duration and sample counts. Service names are preferred and `instance` remains visible as fallback for older targets without a `service` label. Optional host, container, and NGINX metric charts are inside a collapsed row, so unconfigured exporters do not render as four empty panels on the default view. A visible exporter status stat distinguishes NOT CONFIGURED, DOWN, and UP from Prometheus `up` target series; immediately after adding a target, it may remain NOT CONFIGURED until the first scrape creates the series. To diagnose DOWN, open Prometheus **Status → Targets** and inspect that target's **Last scrape error**.

Root cause in source configuration: the four exporter target defaults are blank (`ansible/roles/prometheus_grafana/defaults/main.yml`) and the Prometheus template omits each empty target job, while the previous dashboard queried exporter metric families unconditionally. The app Compose exporter bind defaults are loopback-only and there are no public proxy routes; therefore the dashboard had no evidence the exporters were reachable. This change does not set targets, alter binds, open firewall/routing, or claim that `192.168.0.115:19090` or any exporter is reachable. The application-target inventory still defines six Actuator endpoints; whether those host routes work depends on external network/deployment state. No application-specific metric names are asserted.

Official Grafana v13.3 documentation checked for this dashboard change: [Stat visualization](https://grafana.com/docs/grafana/v13.3/visualizations/panels-visualizations/visualizations/stat/) confirms the **Value and name** display; [Prometheus query editor](https://grafana.com/docs/grafana/v13.3/datasources/prometheus/query-editor/) confirms Instant queries return a single current point per series and are recommended for stat panels; [dashboard provisioning](https://grafana.com/docs/grafana/v13.3/administration/provisioning/) documents file provisioning and configurable polling; [dashboard JSON model](https://grafana.com/docs/grafana/v13.3/dashboards/build-dashboards/view-dashboard-json-model/) documents dashboard JSON models and the classic panels list. On the isolated Docker VM, Prometheus 3.16.0 scraped six distinct fixture upstreams through the Compose proxy with matching service labels; scrape duration and sample counts returned one series per service. Grafana 13.3.0 reported `infra-overview` as provisioned via its dashboard API, and the optional exporter query returned NOT CONFIGURED, DOWN, and UP for the corresponding fixture states. This did not test browser rendering or production application endpoints.

## NGINX log privacy and rotation

NGINX `metrics_safe` access records contain only status, request duration, and upstream response duration; they omit IP, host, URI/path/query, headers, user-agent, and payload. The stub_status listener is on port 8081 inside the app Compose network only, with no host publication or public proxy route.

The NGINX access log is file-based at `/var/log/nginx/access.log`, shared with nginx-log-exporter through the `nginx-access-log` named volume. There is **no bounded rotation configured for these external/file-based NGINX access logs**. Rotation/reopen semantics are **UNVERIFIED**; no rotation mechanism is configured or claimed. Docker stdout/stderr log rotation does not cover log files stored in a mounted volume or bind-mounted files, so file growth remains unbounded.

The nginx-log-exporter v1.11.0 config is now HCL in `proxy/nginxlog-exporter.hcl`, mounted at `/etc/nginxlog-exporter/config.hcl`, and Compose invokes `-config-file` with that path. Exact-version source confirms HCL shape and `listen`, `namespace`, `source.files`, and `format` fields: [v1.11.0 example-config.hcl](https://raw.githubusercontent.com/martin-helmich/prometheus-nginxlog-exporter/76552e7cadc1f76b4e28b5c872412db4a091aca0/example-config.hcl). The CLI flag is source-verified against the [v1.11.0 upstream tree](https://github.com/martin-helmich/prometheus-nginxlog-exporter/tree/v1.11.0). The configured input path and log format match the proxy template and Compose volume. Parser behavior, exported metric names, and file rotation/reopen behavior remain **UNVERIFIED**; no config validator or runtime check was run.
